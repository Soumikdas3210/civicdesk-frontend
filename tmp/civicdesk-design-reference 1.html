How to use this file

This is the single visual source of truth for the CivicDesk frontend. It pairs with Section 16 of the build plan, which explains why each colour was chosen. This file shows what everything looks like.

Rule. If you are about to invent a colour, a spacing value, a font size or a component shape that is not on this page, stop and ask the lead instead. Consistency across three people is worth more than any individual improvement.

Every value below is a CSS variable. In the real project they live in src/app/globals.css and are used through Tailwind. Never write a raw hex in a component.

Colour

Brand hue 211 degrees. Neutrals are the same hue desaturated, not grey. Accent amber 38 degrees is the complement of 211 and is reserved for missed deadlines only.

Buttons

Minimum height 44px. One primary button per screen. Labels say what happens.

Never write "OK", "Submit" or "Yes". Write "Mark as resolved", "Send reply", "Delete department".

Form fields

Label above the field and always visible. Help text under the label. Errors under the field, in words, saying what to do.

Radius: 8px on cards and panels, 6px on buttons and inputs, 999px on badges only. Borders: 1px n-200 everywhere. Shadows only on modals and dropdowns, because those genuinely float above the page. Everything else uses a border.

Checklist before you open a pull request

  • No raw hex, font size or spacing value anywhere except globals.css
  • Loading, empty, error and normal states all built and all tested
  • Every label above its field and visible while typing
  • Field errors under the field, in plain words, saying what to do next
  • One primary button on the screen, and its label says what happens
  • Every tap target at least 44 by 44 pixels
  • Tab through the whole screen, focus ring visible on every stop
  • Screen checked at 390px width
  • Greyscale screenshot still readable
  • No status code, no server jargon, no stack trace visible to the user
